# fd2 Phase 6: independent verification

Verifier: independent agent, 2026-10-14. Scope: the claims in `STATUS.md`, `4_pd2_source/{ProjectDiablo,PD2_EXT}/README.md`,
`5_game_patches/README.md`, `0_inventory/INVENTORY.md` and `tools/README.md`, checked against the Ghidra exports, the
binaries and the reference tree. Nothing in the repo was changed except this file. All scripts and outputs are in
`/home/user/fd2_work/scratch/verify/` (`check1.py` ... `check7.py`, `*_out.txt`, `*_all.txt`). The workspace
(`fd2_work/`, excluding `scratch/`) had the same file list, mtimes and sizes before and after the regeneration run.

**Seed:** every random sample uses `random.seed(20261014)` (Python 3 `random`).

## Method

| # | What was compared | Independent ground truth |
|---|---|---|
| 1 | Tree body vs export body, token by token (comments removed). A token difference counts as explained only if it is `undefinedN`→`uintN_t`, a `ghidra_name`→`new_name` pair from `symbols.csv`, a `DAT_` rename from the `/* was DAT_... */` comments in `globals.h`, a `cell`→`cell_name` from `game_pointers.tsv`, or `_DAT_x`→`DAT_x`. Lines marked `/* not traced by Ghidra */` are dropped (documented). Also checked: the function's file, header comment (`// 0x<addr> (ghidra: X) [conf]`), signature name, and that every call to a lazy thunk uses the thunk's `pd2_name` from `game_pointers.tsv`. | `3_ghidra_fixed/{ProjectDiablo,PD2_EXT}_decompiled.c` + `.extra.c` |
| 2 | Anchors: the own `__FILE__` string addresses were found in `ProjectDiablo.dll` and each anchor function was disassembled (capstone, from its start to the next symbol) for an operand equal to the string's VA. Reverse check: every non-anchor function was scanned the same way. Range/linked/inferred: the `__xc_a` table was read from the binary (jmp stubs followed); link-unit membership, "uses a file-private global" (all users of that global in the export), "between two functions of F" (nearest strong evidence on both sides), "called from F" (callers found in the export). | `bin/ProjectDiablo.dll`, export |
| 3 | `patches.csv`: original bytes read from the stock DLL at module+RVA (on-disk rows: shipped file must hold the new bytes); table entries re-decoded from `.data` (`{nDLL, dwAddress, dwData, bRelative, nPatchSize}`, module names from the 27-entry table at 0x103c68a0; installer semantics read from `FUN_102ad020`: size 0 → one DWORD, rel32 = data − (target+4); size N → `memset` of the low byte); block entries (`{nDLL, addr, DWORD pData[256], size}`); BH/PD2_EXT rel32 to the handler; init writes = LE(handler). `game_function` = reference function start + offset, and that start must be the nearest reference start ≤ VA (or, for `sub_<va>`, an entry the reference lacks). HOOKS.md / FEATURES.md tables recomputed from `patches.csv`. | stock DLLs in `inputs/ProjectD2/ProjectD2/`, `bin/ProjectDiablo.dll`, `sigmaRE/5_game_source/*/symbols.csv` |
| 4 | `game_pointers.tsv`: DLL index and pair table read from the export (or disassembly where the export folds it), `{1.13c, 1.13d}` read as int32 from the pair table, reference name from `exports.tsv` (ordinals), `symbols.csv` (functions, `inside` for code addresses) or `include/globals.h` (data). | binary, export, reference |
| 5 | `dotnet build tools/Fd2Tools.csproj` and `Fd2Tools undeclared <tree>` on both trees (in the repo copy). | |
| 6 | `cp -a` of the repo to `scratch/verify/repo`, then `tools/rebuild.sh --pd2` (repo_root resolves to the copy) and `python3 -I tools/patches/build_patches.py --repo <copy> --work /home/user/fd2_work`; `git status` and `diff -r` against the committed tree. | |
| 7 | Claims in `2_txt/diff/*.md` (added / removed / changed cells) parsed and checked against `2_txt/pd2` and `2_txt/vanilla_113c` using the documented key rule (`#n` for duplicates, 0-based data row index). | txt files |
| 8 | Headline numbers in `STATUS.md` recomputed from `symbols.csv`, `game_pointers.tsv`, `link_units.tsv`, `patches.csv`, the export headers, `0_inventory/base_modules.csv` and the PE checksums. | |

## Verdict

**PASS.** Every sampled claim checked against the Ghidra exports, the binaries and the reference holds. The whole-population
runs agree: every PD2/PD2_EXT function body, every one of the 1,636 patch records, every anchor and all 31,942 data diff claims.
Both trees and `5_game_patches/` regenerate byte-identically from the documented commands. The discrepancies are
documentation-level: stale STATUS numbers, an undocumented name sanitisation, an undocumented and not always exact
`_ReturnAddress()` rewrite, the inferred-rule wording, and the undeclared command's import filter. None of them changes a
result.
