`Project-Diablo-2/BH` at commit `4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a` with no private changes
(`4_pd2_source/BH/README.md`), so every key is linked to that source. All link targets are
`https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/<file>#L<line>`.

## Load rules

* Missing or corrupt file: same scheme as ProjectDiablo.json and d2gl.json (the three share it): create `{}`, fall back
  to `.bak`, reset both to `{}` if the backup is also corrupt; save at the end when the file was (re)created
  ([Config.cpp:293-342, 420-423](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Config.cpp#L293)).
* `GetInt` ([Config.cpp:10-39](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Config.cpp#L10)): value or default, then clamp. **A bound of 0 means "no bound"**
  (`min = def.minValue ? def.minValue : INT_MIN`), so the `bh_ui` coordinates are only clamped from above.
  A value of the wrong JSON type is ignored (exception swallowed) and the default kept. `GetBool`/`GetString` likewise.
* `GetToggle` ([Config.cpp:109-127](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Config.cpp#L109)): object with optional `enabled` (bool) and `hotkey`
  (key name). `GetKey` ([Config.cpp:129-138](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Config.cpp#L129)): key name string.
* Key names are the BH table `pCodes` ([Common.cpp:182-238](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Common.cpp#L182)): `"None"` (0), `"VK_BACK"`,
  `"VK_NUMPAD0"` ... `"VK_QUOTE"`, matched case-insensitively by `GetKeyCode(const char*)`
  ([Common.cpp:246](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Common.cpp#L246)); an unknown name becomes `None`.
* Defaults are the `BHApp` member initializers in [BH.h:49-193](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/BH.h#L49) (`{value, default, min, max}` for ints).

## Notes

* `save_last_game` / `save_last_pass` / `save_last_desc` are runtime state (last game name, **password**,
  description), written back by BH; they are empty in the shipped file and are documented here as `<redacted>`.
* The three loot-filter hotkeys are still read and saved, but BH's own key handling for them is commented out
  ([Item.cpp:836-850](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Modules/Item/Item.cpp#L836)); level changes come from ProjectDiablo.dll through BH's config
  message export (`BH_CONFIG_INCREASEFILTER` / `DECREASEFILTER` / `RESTOREFILTER`, [BH.cpp:406-425](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/BH.cpp#L406)),
  see `4_pd2_source/BH/interop.md`.
* `legacy_settings.drop_notifications` / `close_notifications` / `verbose_notifications` are read, saved and shown
  in BH's settings tab, but the code that printed the notifications is commented out
  ([Item.cpp:1075-1097](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/Modules/Item/Item.cpp#L1075)); drop notifications are now produced by the MapNotify module and controlled by `detailed_notifications` and the filter's `%NOTIFY-xx%`/`%TIER-n%` tokens.
  The other six legacy toggles are live: they shape item names when the loot filter is off (`Item::OrigGetItemName`).
* `bh_ui.size_x` / `size_y` are read and saved but unused (consumer commented out at [BH.cpp:96](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/BH.cpp#L96)).
* `showStatRangesPrimary` / `showStatRangesSecondary` exist in `BHApp` ([BH.h:111-112](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/BH.h#L111)) but are set
  only through the config-message interface, never from BH.json.
* The legacy `ProjectDiablo.cfg` keys map onto this file; see `ProjectDiablo.cfg.md`.
