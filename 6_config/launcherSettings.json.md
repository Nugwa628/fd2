# AppData/launcherSettings.json

Settings and caches of the **PD2 launcher** (`PD2Launcher.exe`, `SteamPD2.exe`; .NET single-file apps). Their
version resource gives the source commit: `ProductVersion 1.0.0+300ed6fbbcb85bf6b02e8bb052e4e0c5f3a77de3`, which is
in the public repo `Project-Diablo-2/PD2Launcher` (2026-07-23, "2.14.0 rought in"). All launcher links point to
`https://github.com/Project-Diablo-2/PD2Launcher/blob/300ed6fbbcb85bf6b02e8bb052e4e0c5f3a77de3/<file>`. **BH.dll** also reads two fields of this file to pick the loot filter.

| Section | Read by |
|---|---|
| `DdrawOptions` | Launcher only. ## Loot-filter selection (BH.dll)

`BH::LoadLootFilter` ([BH.cpp:189-230](https://github.com/Project-Diablo-2/BH/blob/4f7b4d7cd3915b8f60f5d4fcc820f5a7e98ec71a/BH/BH.cpp#L189)) opens `./AppData/launcherSettings.json` (relative to the
working directory) with nlohmann::json. Only if `SelectedAuthorAndFilter.selectedAuthor.author` and
`SelectedAuthorAndFilter.selectedFilter.name` both exist does it use them: `filters\local\<name>` when the author
is `"Local Filter"`, else `filters\online\<name>` (relative to BH's module directory). If that file cannot be
parsed, or the keys are missing (as in the shipped file, where both are `null`), it falls back to `loot.filter`, then
`default.filter`, then shows "Could not find default loot filter". The launcher writes the selected online filter to
`filters\online\<name>` (`FilterHelpers` [PD2Shared/Helpers/FilterHelpers.cs:328](https://github.com/Project-Diablo-2/PD2Launcher/blob/300ed6fbbcb85bf6b02e8bb052e4e0c5f3a77de3/PD2Shared/Helpers/FilterHelpers.cs#L328)-342) and refreshes it before
each launch when its `sha` changed ([PD2Launcherv2/MainWindow.xaml.cs:248](https://github.com/Project-Diablo-2/PD2Launcher/blob/300ed6fbbcb85bf6b02e8bb052e4e0c5f3a77de3/PD2Launcherv2/MainWindow.xaml.cs#L248)-252). The filter grammar is in `filter-format.md`.

## Findings

* `FileUpdateModel.Other` is never read.
* `LauncherArgs.skiptobnet` defaults to `true` in the model but is `false` in the shipped file (user choice).
* The shipped `DdrawOptions` equal the model defaults (`new DdrawOptions()`), not the shipped `ddraw.ini`
  (e.g. `Width` 0 vs `width=1068`): the launcher last stored the section when `ddraw.ini` could not be read (the
  `ReadDdrawOptions` catch path). Since `graphics=false`, ddraw.ini is not used anyway.
* `DdrawOptions.Resizeable` has no effect (misspelled ini key, see `ddraw.ini.md`).
