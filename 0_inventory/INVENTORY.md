## 1.13c game modules

Every Blizzard module PD2 ships is the 1.13c build: link timestamps 2010-03-09, PDB paths
`X:\trunk\Diablo2\Builder\PDB\*.pdb`, `Game.exe` version 1.0.13.60. Compared with the sigmaRE
reference (`5_game_source\<Module>`, built from Median XL's 1.13c install):

* **Exports:** all ordinals of all 19 DLLs have the same RVA as in the reference (Storm compared
  after rebasing: the reference loaded it at 0x6f600000, the file's base is 0x6fbf0000).
* **Function starts:** every reference function start lies in `.text` of the shipped file
  (Fog: 843 of 844, the extra one is a trailing lib stub).

So the reference names (`symbols.csv`, `exports.tsv`) apply directly to the PD2 modules.

The vanilla install (`C:\Program Files (x86)\Diablo II`) was not available, so there is no byte
diff yet. Instead each file's stored PE checksum was compared with a recomputed one. Blizzard's
linker set it, and a patcher that edits bytes almost never updates it:

| Module | PE checksum | Verdict |
|---|---|---|
| D2Win.dll | **mismatch** | **byte-patched** (details below) |
| Storm.dll | **mismatch** | **byte-patched** (details below) |
| Diablo II.exe | not set (2001 VC6 build) | can't tell this way; it's the 1.0.0.1 launcher stub |
| all 18 others | matches | identical to the original build |

### Patches found so far

1. **Storm.dll, import table:** the import descriptor that read `VERSION.dll` now reads
   `PD2_EXT.dll` (same length, 11 characters, `.rdata` file offset 0x4e63a). Storm imports
   `GetFileVersionInfoA`, `GetFileVersionInfoSizeA` and `VerQueryValueA` from it, so Windows loads
   `PD2_EXT.dll` as soon as Storm loads. That is PD2's first code to run in the game process.
2. **D2Win.dll, `D2Win_10086` (MPQ loader, `between_Src_D2WinArchive_and_Src_D2Comp.cpp` in the
   reference):** at 0x6f8eab47 the original `mov eax,1; ret` became `jmp 0x6f8fa2a1; ret`.
   0x6f8fa2a1 is a code cave just past `.text`'s virtual size (inside its raw padding):
   `push "ProjectDiablo.dll"` (string placed at 0x6f8fe378 in `.rdata` padding);
   `call [LoadLibraryA]`; `mov eax,1`; `ret`. So `ProjectDiablo.dll` is loaded right after the
   base MPQs open.

Both are consistent with the reference decompile (Median XL's D2Win still shows `return 1` there).
A full byte diff needs vanilla 1.13c `D2Win.dll` and `Storm.dll` (see open questions). Phase 4 checked both
(`5_game_patches/README.md`): D2Win also has 17 redirected string operands pointing its base-MPQ names at new
`..\\d2*.mpq` strings in `.rdata` padding; undoing all D2Win changes restores the stored PE checksum exactly.
Storm: only the import rename was found, but its checksum still mismatches after undoing it, so a non-code
change (or a stock file with a bad checksum) cannot be ruled out.

## Launcher and updater

`PD2Launcher.exe` (32 MB), `SteamPD2.exe` and `UpdateUtility.exe` are .NET **single-file apphost**
bundles (the native host's PDB is `...\corehost\apphost\standalone\apphost.pdb`, 2024-06-14). The
managed assemblies sit in the bundle, so they can be extracted and decompiled as IL (Phase 5) with
no native decompiling. The launcher downloads `https://pd2-launcher.projectdiablo2.com/launcher_manifest.json`
(from `update.log`); `local_metadata.json` holds MD5s of every installed file, which the updater checks.

## Recommended work order

1. **Tooling:** build StormLib (MPQ) and Ghidra 12.1.4 headless in the workspace (no Ghidra
   install was uploaded; both build from source here). Port the sigmaRE C# generators to the
   container (needs .NET SDK or a Python port).
2. **Phase 1 (data)** and **Phase 2 (decompile)** in parallel:
   * Phase 1: extract `pd2data`/`patch_d2`/`pd2maps`, decode tables.
   * Phase 2: `ProjectDiablo.dll` (largest, ~3.3 MB code), `PD2_EXT.dll` (small, do first: it
     shows the loader and early patches), `BH.dll`.
   * The 1.13c modules need no decompile: 19 are identical, and D2Win/Storm differ only by
     small byte patches that can be described from the reference decompile.
3. **Phase 3:** source trees for PD2_EXT, then ProjectDiablo. Primary file evidence: the
   `D2TemplateSource\ProjectDiablo\...\*.cpp` assert paths (link order to be tested).
4. **Phase 4:** hooks: D2Template's patch tables in ProjectDiablo.dll, PD2_EXT's
   `VirtualProtect` patches, and the two on-disk patches above.
5. **Phase 5:** configs, BH diff against `Project-Diablo-2/BH`, D2GL diff, launcher IL.
6. **Phase 6:** verification and final README numbers.
