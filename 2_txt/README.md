# 2_txt: PD2 data tables, vanilla 1.13c baseline, diffs

Phase 1 (data) output. Everything here except this README is generated by the scripts in
`tools/`; do not hand-edit. No binary MPQ content is committed: only text tables, decoded string
tables, raw-number dumps of `.bin` tables, listings and diffs.

## Layout

| Path | Contents |
|---|---|
| `pd2/<table>.txt` | 93 PD2 excel tables: byte copies of `pd2data.mpq` `data\global\excel\*.txt` (file names lower-cased) |
| `pd2/raw_dumps/` | 5 PD2 `.bin` tables shipped without a `.txt`: `leveldefs` (u8@offset columns), `itemscode`, `misscode`, `skillscode`, `skilldesccode` (compiled formula byte code, hex) |
| `pd2/strings/patchstring.tbl.txt` | PD2 `data\local\LNG\ENG\patchstring.tbl`, 2,980 strings, `key<TAB>value` |
| `pd2/other/ExpansionCredits.txt` | `data\local\ui\eng\ExpansionCredits.txt` (UTF-16 in the MPQ, UTF-8 here) |
| `pd2/TABLES.md` | per table: .txt rows/cols, .bin records/record size, which vanilla baseline exists |
| `vanilla_113c/` | stock 1.13c tables from `patch_d2.mpq`: 62 `.txt`, `raw_dumps/` for 8 tables that are `.bin`-only there, `strings/patchstring.tbl.txt` (English, 1,169 strings) |
| `diff/<table>.md` | 65 table diffs + `patchstring.tbl.md`; index and "no baseline" list in `diff/README.md` |
| `PD2_ONLY.md` | tables with no stock counterpart, plus stock tables whose `.bin` layout PD2 changed |
| `MPQ_LISTING.md` | every MPQ: counts, sizes, by type, by folder |
| `listings/<mpq>.tsv` | full file list per MPQ: path, size, compressed size, type |

## How it was produced

```
tools/phase1_data.sh <PD2 dir> <StormLib src> <listfile dir> <work dir>
```

1. `tools/mpq/build.sh`: StormLib (git HEAD 116135c, shared, bundled zlib/bzip2/libtom*) and
   `mpqx` (`tools/mpq/mpqx.cpp`): `mpqx list|extract <mpq> <out> [listfile...]`. StormLib
   handles PKWARE implode, zlib, bzip2, Huffman/ADPCM.
2. `tools/mpq/run_all.sh`: lists all 8 MPQs; builds a candidate listfile
   (`tools/mpq/make_listfile.py`, 38,234 names) from the archives' own `(listfile)`s, `data\...`
   strings in every PD2 DLL/EXE (ASCII and UTF-16, with D2 extensions appended), every
   `*invfile`/`flippyfile` value in PD2's excel tables, all excel table names, `.tbl` names for 11
   language folders, localised act-label names (`data\local\ui\<lang>\Expansion\A5L28.dc6`...),
   and three public listfiles (in the workspace `ext/listfiles/use/`, not committed):
   the Diablo II list inside WinMPQ's `LISTFILE.DAT` (github `buuug7/diablo-113c`),
   `filenames.txt` of UdieToo (github `GarnetRapture/UdieToo`) and the `patch_d2.mpq/(listfile)`
   of the mod github `xPh03n1x/eastern-sun-hd`. Then lists again with it and extracts
   pd2data, patch_d2, pd2maps, SGD2FreeRes, D2MultiRes and d2gl to
   `fd2_work/1_bin_from_mpq/<mpq>/` (folders merged case-insensitively).
3. `tools/mpq/listing_report.py`: `MPQ_LISTING.md`, `listings/*.tsv`.
4. `tools/data/build_tables.py` (uses `tools/data/tbl2txt.py`): copies, dumps, decodes and diffs.

Running it twice gives identical output.

(Counts include each archive's `(listfile)` where present.)

- Excel tables in pd2data: 98 (93 with `.txt`, all copied; 5 `.bin`-only, raw dumps). pd2data
  ships both `.txt` and `.bin` for 85 tables; for each, the `.bin` record count matches the
  `.txt` row count (minus `Expansion` separator rows), so the `.txt` files describe what the game
  loads.
- Strings: 1 `.tbl` in pd2data (English `patchstring.tbl`, 2,980 entries). PD2 ships no
  `string.tbl` / `expansionstring.tbl`, so the stock ones apply. All `.tbl`s (stock and PD2) store
  UTF-8 (`ÿc` colour codes are bytes C3 BF 63).
- Diffs: 62 tables against the stock `.txt`, 3 (`automagic`, `rareprefix`, `raresuffix`)
  record-by-record against the stock `.bin`, plus `patchstring.tbl`. 33 tables have no
  baseline (see `diff/README.md`).
- PD2-only tables: 1 (`MiniSkillIcons.txt`, a skill-id → mini-icon frame map, not compiled).
  PD2 also changes the layout of a stock table: `itemstatcost.bin` grows from 324 to 336 bytes
  per record (new columns `Save Bits S12`, `Save Add S12`, `Save Param Bits S12`).

## patch_d2.mpq verdict: stock 1.13c, unmodified by PD2

Evidence:
- It has no `(listfile)` or `(attributes)`, like Blizzard's patch MPQs. Every PD2-built archive
  (pd2data, pd2maps, pd2assets, pd2monchars) carries a `(listfile)`.
- Its 209 files are exactly the content of a Blizzard 1.13 patch: 70 excel tables (62 `.txt`, 67 `.bin`;
  stock 1.13c record sizes), `patchstring.tbl` in 9 languages (chi deu eng esp fra ita
  jpn kor pol), `data\local\MacUI\*\D2Resources.rsrc` (4 languages), `data\IAmExpansion`, Act 4
  Chaos Sanctuary `.ds1` presets, `townWest.ds1`, localised `A5L28-31.dc6` act labels in 9
  languages, 1.10-1.13 item graphics (`invtoa`, `invtes`, `invceh`, `invbet`, `invfed`,
  `invrVex`), Werebear bite sounds and `gem.wav`, Battle.net front-end `.dc6`s. No path refers to
  PD2 content (maps, PD2 UI, SGD2FreeRes).
- Table contents are stock: armor 202, weapons 306, misc 151, uniqueitems 402, runes 169,
  itemstatcost 359 rows; Misc.txt has the 1.13 Token of Absolution and the four essences; no PD2
  code appears (no `map-*` properties, no `t11`... map items, no S12 columns).
- Each `.bin` record count equals its `.txt` row count, i.e. the bins were compiled from these
  txts (no PD2 bins slipped in).
- Caveat: no reference hash of the 1.13c `patch_d2.mpq` was available to compare against, and
  1.13c vs 1.13d cannot be told apart from content alone. The game modules are 1.13c (Phase 0).

## Missing / not done

- Stock `d2data.mpq` / `d2exp.mpq` were not provided, so 33 tables (arena, armtype, automap,
  belts, bodylocs, chartemplate, colors, composit, gamble, hiredesc, hitclass, inventory... see
  `diff/README.md`) and `string.tbl` / `expansionstring.tbl` have no baseline. A Diablo II
  install with those MPQs exists in the public repo github `buuug7/diablo-113c` (unverified,
  third-party upload; not used).
- `automagic`, `rareprefix`, `raresuffix` diffs are byte-level (record/offset) because patch_d2
  has only their `.bin`; column names need the 1.13c record layouts.
- The `*code.bin` formula blobs and `leveldefs.bin` are dumped, not decoded.
- PD2-specific `.bin` layout (`itemstatcost` +12 bytes) and the added columns that do not change
  record sizes (e.g. `levels` mon11-25 / nmon / umon, `misc` `auto prefix`/`normcode`/...,
  `weapons` stat1-3/calc1-3/spelldesc) need the DLL side (later phase) to know how they are read.
- pd2assets / pd2monchars / pd2maps assets (images, `.ds1`, `.dcc`) are listed, not decoded.
